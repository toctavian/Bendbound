# POI and Fuel Finder service

The source in [routing/poi/service.py](../routing/poi/service.py) runs on the existing London EC2 host as `bendbound-poi.service`. It uses Python's installed AWS SDK and the EC2 instance role to read the Fuel Finder secret into memory. OAuth credentials and tokens are not stored in the service files, SQLite, systemd configuration, logs or the mobile bundle.

Caddy authenticates the endpoints using the existing pilot bearer token and forwards requests to `172.18.0.1:8090`, the private Docker bridge gateway on this host. The service binds to that gateway rather than a public interface. Routing, database and Valhalla services are not rebuilt or restarted by the POI deployment. The dedicated service user has no login shell; systemd limits memory to 256 MiB and protects system/home directories. The service restarts automatically after failures/reboots.

## App configuration

The local `.env` and public `.env.example` include:

```dotenv
EXPO_PUBLIC_POI_URL=https://api.bendboundapp.com/pois
EXPO_PUBLIC_FUEL_PRICES_URL=https://api.bendboundapp.com/fuel-prices
```

The app sends the existing `EXPO_PUBLIC_ROUTING_TOKEN` as a bearer header. That pilot token is already visible in the mobile bundle; it is not a Fuel Finder OAuth credential. When producing a cloud build, configure these public endpoint values and the existing routing token in its build environment. Restart Metro/rebuild to pick up environment changes. Existing installed TestFlight binaries cannot acquire these code changes without a new build; this project has no configured EAS Update runtime.

## Endpoints

- `GET /pois?category=fuel|meet|sight|forest|pass&latitude=...&longitude=...&radius=...`: nearby places. Results are ordered by geographic distance, with a cap of 80. Fuel stations come from Fuel Finder and carry stable forecourt IDs. Closure information remains visible. A supplier-neutral postcode consistency check using [Postcodes.io](https://postcodes.io/docs/api/bulk-postcode-lookup/) excludes obvious map errors (published coordinates more than 5 km from a known postcode centre), while retaining original station/price records and allowing exact-ID price lookups. Postcode metadata is cached for thirty days. Coordinates are not replaced with invented locations; unresolved postcodes retain their provider location. The check was added after a Lancashire forecourt was observed with published London coordinates. Meets use the reviewed venue catalogue directly. Forest searches prioritise reviewed public routes through Epping Forest (A104) and the Forest of Dean (B4226), confirmed against current OSM road geometry. Outside those reviewed routes, discovery requires ordinary public roads in at least 25 hectares of named woodland. Residential streets, pocket copses, parks, restricted roads and unpaved tracks are excluded.
- `GET /fuel-prices?stationId=...`: original per-grade prices and timestamps for that exact forecourt. Unknown IDs, incomplete data and unverified/stale data return an explicit unavailable response. All fuel grades, including grades whose provider price is null, are retained. The provider may omit site-update timestamps: `updatedAtBasis=latest-price-update` labels the latest original price timestamp without inventing site metadata. Per-grade effective timestamps are also displayed.
- `POST /route-pois` with `{ "route": [ { "latitude": 51.5, "longitude": -0.1 }, ... ] }`: bounded, validated route-corridor discovery. The app submits its simplified corridor and projects returned places onto the complete route. Fuel Finder stations along the corridor retain their stable IDs.
- `GET /poi-photo?wikipedia=en:Place`: cached Wikipedia thumbnail metadata. Only Wikipedia language hosts and Wikimedia thumbnail URLs are supported.
- `GET /poi-health`: sync readiness, dataset counts, last upstream verification time and polling statistics. This endpoint is authenticated too.

OSM queries are generated by the service, not accepted as arbitrary client queries. Query concurrency is limited to two, results are cached for five minutes (thumbnail metadata for a day), and request/radius/body bounds prevent unbounded searches. Forest results depend on mapped polygon and access/surface coverage. Closed ways and reconstructable multipolygon relations are supported, including exclusion of inner holes. The server fetches named forest boundaries first, then roads within their bounding boxes, and checks each pin against the actual polygon. Because OSM woodland boundaries often stop at road edges, narrow road gaps also qualify when mapped woodland lies on opposing sides within 40 metres. A road beside one park edge does not qualify. Incomplete boundaries and ambiguous/private roads are omitted.

## Fuel synchronization

A single background worker initially fetches every page of prices and forecourt information, then polls both incremental endpoints every four minutes with a sixty-second overlap. It performs a full reconciliation hourly. Short pages do not imply completion: the worker fetches through the provider's terminal 404, treats empty 200 responses as transient and fails rather than publishing incomplete data. Calls are sequential and paced below the official limit of 100 requests/minute; a valid OAuth token is reused until near expiry.

A complete successful cycle updates the two datasets and cursor atomically. Incremental price updates merge by fuel grade, preserving unchanged grades and metadata. A failed second endpoint cannot publish a partial cycle or advance the cursor. Original upstream records are retained in SQLite at `/var/lib/bendbound-poi/fuel.sqlite`; these contain public forecourt/price data, not credentials. The upstream verification time is the start of the successfully completed cycle, not the time the app reads a cached price.

Prices verified more than five minutes ago are unavailable. Error retries back off, respect rate-limit retry windows, and never advance freshness on failure. SQLite keeps poll outcome/coverage/API-call records for ninety days. The authenticated health endpoint reports daily success-gap statistics; `journalctl -u bendbound-poi.service` provides structured, non-sensitive request/sync events. Outages can still interrupt freshness; they must be mitigated and monitored according to the [saved terms](legal/fuel-finder-access-terms.md). This implementation and short deployment checks cannot establish future daily compliance.

The app preserves price precision, timestamps and missing grades, links to discrepancy reporting and includes Fuel Finder/Open Government Licence attribution. POI records identify their source; raw complete Fuel Finder API payloads are not exposed by the public app endpoints.

## Deployment and rollback

The [deployment script](../routing/poi/deploy.py) verifies the expected private gateway and SDK availability, backs up the previous service and Caddy configuration, installs the unit and service, validates Caddy's configuration and reloads only Caddy. Failed deployments restore the previous Caddy file and stop or restore the POI service. Deploy through AWS MCP/SSM using a checksummed archive containing only the explicit service/config/test files; never include `.env` or `.secrets.env`.

Prepare a credential-free archive and AWS MCP `SendCommand` script with `python3 scripts/prepare-poi-release.py`; the script writes the reviewable payload and checksums under `/tmp`.

The deployment record is [routing/poi/deployment.json](../routing/poi/deployment.json). The backup directory recorded there retains the previous configuration. To roll back through AWS MCP/SSM, restore that backed-up Caddyfile in place (preserving its mounted inode), validate/reload Caddy, and restore or disable the POI unit as appropriate. Price data is kept separately from service releases.

Local checks: `python3 -m unittest discover -s routing/poi -p 'test_*.py'`, `npm test`, `npm run lint`, `npm run typecheck`. `node scripts/poi-live-smoke.mjs` exercises all five categories, prices, route POIs, thumbnails, authentication and the existing routing health endpoint using the local public pilot configuration. It does not read OAuth credentials.

Reviewed forest-route evidence: [Essex Highways A104 Epping New Road](https://www.essexhighways.org/highway-schemes-and-developments/highway-schemes/epping-forest-schemes/epping-new-road) and [Forestry England directions via the B4226](https://www.forestryengland.uk/beechenhurst/activities). These records are a small reviewed catalogue, not exhaustive woodland coverage.
